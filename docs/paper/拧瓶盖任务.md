# Vial Capping / Decapping Benchmark 施工文档（MuJoCo v1）

## 0. 文档目的

本文档用于指导 Claude Code 开发一个 **MuJoCo 中的样品瓶封盖 / 开盖 benchmark 任务**。  
该任务是 `paper-to-benchmark` 路线下的第一个模板任务，目标不是高保真复现真实螺纹物理，而是构建一个：

- **可执行**
- **可自动判分**
- **可解释 failure mode**
- **适合评测 VLM/VLA protocol correctness**

的 benchmark 环境。

本任务应优先服务于 benchmark 研究，而不是追求复杂接触动力学或真实工业级控制。

---

# 1. 任务定义

## 1.1 总体目标

构建两个任务：

1. **Vial Capping**
   - 机器人抓取瓶盖
   - 将瓶盖移动到固定瓶身上方
   - 对齐瓶口
   - 执行“旋紧”
   - 达到封盖完成状态

2. **Vial Decapping**
   - 机器人抓取已经锁紧的瓶盖
   - 按正确方向旋转“解锁”
   - 将瓶盖抬离瓶口
   - 达到开盖完成状态

---

## 1.2 设计原则

### 必须满足
- 单臂任务
- 瓶身固定在工装/夹具上
- 瓶盖为可抓取刚体
- ground truth 可自动验证
- protocol correctness 可通过事件日志验证
- 不依赖高保真螺纹网格

### 明确不做
- 不做真实螺纹几何啮合
- 不做双臂协作
- 不做复杂液体/反应模拟
- 不做真实扭矩控制 benchmark
- 不把“看起来像瓶子”当成交互机制来源

---

# 2. 任务对象设计

## 2.1 核心对象

### Bottle Body（瓶身）
- 固定在桌面夹具上
- 不允许自由移动
- 具有：
  - 瓶口中心点
  - 瓶口法向方向
  - 瓶口接触区域
  - 封盖目标位姿

### Cap（瓶盖）
- 可抓取刚体
- 初始位于桌面指定区域
- 具有：
  - 抓取区域
  - 对齐参考轴
  - 接触底面
  - 相对瓶口的目标位姿

### Fixture（夹具）
- 固定瓶身
- 防止瓶身在封盖/开盖过程中移动
- 仅作为背景支撑，不作为主要交互对象

### Robot Arm / Gripper
- 单机械臂 + 单夹爪
- 可简化为已有操作器模板
- 只要求支持：
  - 抓取
  - 移动
  - 保持姿态
  - 绕工具轴旋转
  - 抬升 / 下压

---

## 2.2 对象几何建议

### Bottle
建议用简化几何：
- 瓶身主体：圆柱
- 瓶口：较小圆柱台阶
- 夹具：U 型或圆环固定座

### Cap
建议用简化几何：
- 主体：中空或近似中空圆柱
- 外表面：便于抓取的凸起可省略
- 接触底面：平面或浅凹面

### 原则
**先做功能等价几何，再决定是否替换成 Objaverse 外观 mesh。**

即：
- v1 用简化 primitive 做交互
- 后续可把外观 mesh 贴到 visual geom 上
- collision geom 保持简单

# 3. 交互机制设计

## 3.1 总体思路

不实现真实螺纹，而实现一个 **任务等价的封盖机构**：

- 位置与姿态满足条件时，进入 `engaged`
- 在 `engaged` 状态下按正确方向旋转超过阈值，进入 `locked`
- 在 `locked` 状态下按反方向旋转超过阈值，进入 `unlocked`
- `unlocked` 后允许瓶盖抬离瓶口，进入 `detached`

---

## 3.2 状态机

### 状态集合
- `FREE`：瓶盖未与瓶口接触
- `ALIGNED`：瓶盖与瓶口位置/姿态接近，但尚未接触
- `ENGAGED`：瓶盖与瓶口完成接触配合
- `LOCKED`：瓶盖已旋紧
- `UNLOCKED`：瓶盖已解锁但尚未移开
- `DETACHED`：瓶盖已从瓶口移除

### 状态转移

#### 封盖
- `FREE -> ALIGNED`
  - 条件：瓶盖中心接近瓶口中心，姿态误差小于阈值
- `ALIGNED -> ENGAGED`
  - 条件：瓶盖下压至接触高度
- `ENGAGED -> LOCKED`
  - 条件：沿正确方向累计旋转角度 >= `theta_lock`

#### 开盖
- `LOCKED -> UNLOCKED`
  - 条件：沿相反方向累计旋转角度 >= `theta_unlock`
- `UNLOCKED -> DETACHED`
  - 条件：瓶盖高度高于释放阈值 `h_release`

### 非法转移
- `FREE` 状态下直接锁紧
- 未对齐直接进入 `ENGAGED`
- `LOCKED` 前直接抬起视为失败
- 错误方向旋转不能触发锁定/解锁

# 4. Ground Truth 定义

## 4.1 Vial Capping 成功条件

任务成功当且仅当同时满足：

1. `cap_state == LOCKED`
2. 瓶盖相对瓶口的位置误差 < `eps_pos`
3. 瓶盖相对瓶口的姿态误差 < `eps_rot`
4. 累计旋紧角度 >= `theta_lock`
5. 瓶盖高度达到锁紧高度范围
6. 无 hard violation
7. 在任务结束前瓶盖未掉落

---

## 4.2 Vial Decapping 成功条件

任务成功当且仅当同时满足：

1. 初始状态为 `LOCKED`
2. `cap_state == DETACHED`
3. 累计解锁角度 >= `theta_unlock`
4. 瓶盖抬升高度 >= `h_release`
5. 瓶盖仍被抓持或已移到安全放置区
6. 无 hard violation

---

## 4.3 Hard Violations

### 封盖
- 未抓取瓶盖就尝试封盖
- 未对齐直接强行下压
- 错误方向旋转
- 瓶盖掉落到地面
- 机械臂将瓶盖推离可恢复区域
- 任务时间内未进入 `LOCKED`

### 开盖
- 未抓住瓶盖直接尝试旋开
- 错误方向旋转
- 未解锁前直接大幅抬起
- 瓶盖掉落
- 解锁失败后强行拉拽导致异常偏移
- 任务时间内未进入 `DETACHED`

---

# 5. Protocol 规范

## 5.1 Capping 的关键事件

必须记录以下事件：

- `pick_cap`
- `move_above_bottle`
- `align_cap`
- `lower_to_engage`
- `rotate_clockwise`
- `lock_complete`

### 偏序约束
- `pick_cap < move_above_bottle`
- `move_above_bottle < align_cap`
- `align_cap < lower_to_engage`
- `lower_to_engage < rotate_clockwise`
- `rotate_clockwise < lock_complete`

---

## 5.2 Decapping 的关键事件

必须记录以下事件：

- `grasp_locked_cap`
- `engage_decap_rotation`
- `rotate_counterclockwise`
- `unlock_complete`
- `lift_cap`
- `move_cap_to_safe_zone`（可选）

### 偏序约束
- `grasp_locked_cap < engage_decap_rotation`
- `engage_decap_rotation < rotate_counterclockwise`
- `rotate_counterclockwise < unlock_complete`
- `unlock_complete < lift_cap`

---

# 7. 事件提取逻辑

## 7.1 事件判定建议

### `pick_cap`
当 `gripper_holding_cap == true` 且瓶盖从桌面离开超过高度阈值

### `move_above_bottle`
当瓶盖中心进入瓶口上方圆柱区域

### `align_cap`
当：
- `alignment_error_pos < eps_align_pos`
- `alignment_error_rot < eps_align_rot`

### `lower_to_engage`
当：
- 已处于 `ALIGNED`
- `cap_height_relative_to_mouth <= h_engage`

### `rotate_clockwise`
当处于 `ENGAGED` 且正向累计角度持续增加

### `lock_complete`
当 `cap_state` 首次进入 `LOCKED`

### `unlock_complete`
当 `cap_state` 从 `LOCKED` 首次进入 `UNLOCKED`

### `lift_cap`
当 `cap_state == UNLOCKED` 且 `cap_height_relative_to_mouth >= h_release`

# 8. 评分设计

## 8.1 最终输出字段

每个 episode 至少输出：

- `outcome_success`
- `protocol_adherence_score`
- `state_validity_score`
- `hard_violation_count`
- `failure_tags`
- `event_trace`

---

## 8.2 推荐评分方式

### Outcome Success
- 成功：1
- 失败：0

### Protocol Adherence Score
按关键事件覆盖率 + 偏序约束满足率计算，例如：

- 事件覆盖率：`covered_events / mandatory_events`
- 顺序得分：`satisfied_order_rules / total_order_rules`

### State Validity Score
用于衡量最终状态接近程度，例如：
- 位置误差
- 姿态误差
- 锁紧角度达成率
- 解锁/抬升达成率

### Scientific/Task Validity
可定义为：
- `outcome_success == 1`
- `hard_violation_count == 0`
- `protocol_adherence_score >= threshold`
