## ⚠️ 遇到的问题和挑战

### 1. 数据格式不匹配问题（已解决）
**问题描述**: 
- VLABench数据集使用`actions`（复数）列名
- LeRobot框架期望`action`（单数）列名
- ACT模型期望`observation.state`格式，但数据集返回`state`

**解决方案**:
- 修改数据集列名：`actions` → `action`
- 保留原始数据格式，不修改lerobot代码

### 2. HuggingFace datasets 5.0+兼容性问题（已解决）
**问题描述**:
```python
# 在datasets 5.0+中，这会失败：
result[key] = torch.stack(list(selected[key]))
# 错误：TypeError: stack(): argument 'tensors' (position 1) must be tuple of Tensors, not Column
```

**解决方案**:
- 添加了`hf_transform_to_torch`进行类型转换
- 后来为了保持纯净性，恢复了原始代码并采用其他解决方案

### 3. 键名前缀问题（待解决）
**问题描述**:
- ACT模型期望：`observation.state`, `observation.image`
- 数据集实际返回：`state`, `image`

**当前状态**: 
- ⏸️ 暂停，等待决策采用哪种解决方案

## 🚨 风险评估

### 高风险
1. **内存不足**: batch_size=8可能导致OOM
   - **缓解方案**: 准备降低到batch_size=4
   - **监控方案**: 实时监控GPU内存使用

2. **训练不稳定**: ACT模型对数据格式敏感
   - **缓解方案**: 从小batch开始，逐步增加
   - **监控方案**: 密切关注loss变化

### 中风险
1. **性能问题**: 多workers可能导致数据加载瓶颈
   - **缓解方案**: 可以尝试num_workers=2
   - **监控方案**: 监控data loading time

## 📝 关键学习点和经验

### 1. 数据格式兼容性
- 不同框架对数据格式的要求可能差异很大
- 在修改框架代码之前，优先考虑修改数据格式
- 版本升级（如datasets 5.0）可能带来不兼容的变更

### 2. 调试策略
- 系统性地从数据流向模型逐步验证
- 每次只修改一个变量，便于定位问题
- 保留修改记录，便于回滚

### 3. 架构决策
- 保持框架代码纯净通常是最好的选择
- 适配器模式是解决兼容性问题的强大工具
- 文档化所有决策和理由，便于团队协作
