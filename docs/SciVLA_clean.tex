\begin{abstract}
Embodied agents are increasingly deployed in scientific laboratories, yet systematically benchmarking their capabilities remains an open challenge. While simulation-based evaluation has become the standard paradigm, existing benchmarks suffer from three key limitations. First, they lack a structured task framework, reducing evaluation to isolated operations rather than capturing higher-level competency dimensions. Second, manual task design fundamentally limits scale, failing to cover diverse instructions and complex, operation sequences. Third, the absence of external disturbances—such as human interventions—precludes the assessment of human–robot collaboration.
To fill this gap, we introduce SciVLABench, a large-scale, comprehensive benchmark for evaluating embodied scientific agents in realistic laboratory settings. In contrast to prior manual efforts, SciVLABench employs an automated task generation pipeline grounded in over 20 curated real-world experimental scenarios. It systematically evaluates eight core capability dimensions—including liquid transfer, physical mixing, thermodynamic control, equipment assembly, and experimental safety—through more than 1,000 complexity-stratified task templates, yielding a task pool 20 times larger than that of the previous largest benchmark. The tasks span basic actions, long-term autonomous experiments, and human–robot collaborative scenarios, providing a fine-grained testbed for model evaluation.  SciVLABench is available at
https://github.com/kaikai-2022/SciVLABench
\end{abstract}

\section{Introduction}

Driven by recent advances in multimodal perception, reasoning, and decision-making, artificial intelligence (AI) is rapidly extending from digital environments into the physical world through embodied agents. While remarkable progress has been achieved in domains such as household assistance and industrial automation, scientific laboratories remain one of the most challenging frontiers for embodied intelligence. Unlike general environments, laboratory tasks require agents to integrate dexterous manipulation, procedural understanding, scientific knowledge, and safety awareness throughout experimental execution. As embodied agents are increasingly envisioned as autonomous scientific assistants, systematically evaluating their readiness for laboratory environments has become an important and timely research problem.

Developing and evaluating embodied agents in real laboratories is prohibitively expensive, difficult to scale, and inherently risky. Consequently, high-fidelity simulation has emerged as an indispensable paradigm for developing and evaluating scientific embodied intelligence in a safe, scalable, and reproducible manner, leading to the emergence of simulation-based laboratory benchmarks. Nevertheless, a fundamental question remains largely unexplored: \textbf{how should scientific laboratory intelligence be systematically evaluated?}

Existing laboratory benchmarks primarily organize evaluation around execution characteristics, such as manipulation operations and task complexity (e.g., short- and long-horizon tasks). While this perspective effectively measures how well agents execute laboratory tasks, it provides only a partial view of laboratory intelligence. Scientific experiments naturally follow a \textbf{perception–cognition–interaction} loop, requiring agents to continuously perceive laboratory environments, acquire scientific understanding, and perform corresponding experimental operations. Consequently, evaluating agents solely from execution characteristics offers limited insight into the scientific capabilities required for successful experimentation.

This observation motivates a complementary \textbf{capability-oriented} evaluation framework that focuses on the competencies exercised throughout scientific experimentation rather than only execution behavior. Building such a framework presents four key challenges: (1) establishing a principled taxonomy that decomposes laboratory intelligence into representative capability dimensions; (2) enabling scalable generation of diverse laboratory tasks beyond manually curated benchmark suites; (3) constructing realistic simulation environments that faithfully reproduce representative physicochemical processes together with dynamic state transitions; and (4) treating laboratory safety as an inherent component of scientific intelligence rather than an isolated evaluation criterion.

To address these challenges, we present \textbf{SciVLABench}, an open-source benchmark for comprehensive evaluation of scientific embodied intelligence. SciVLABench is built upon four complementary components. First, it establishes a structured evaluation taxonomy that organizes scientific embodied intelligence into representative dimensions spanning \textbf{scientific cognition} and \textbf{scientific practice}. Second, it introduces an automated task generation pipeline that enables scalable construction of large-scale and diverse laboratory tasks beyond manually curated benchmarks. Third, it incorporates a high-fidelity laboratory simulation environment supporting representative physicochemical processes, dynamic laboratory interactions, and event-driven state transitions throughout experimental procedures. Finally, it integrates laboratory safety throughout the evaluation framework, assessing not only task completion but also safety-aware decision-making during experimental execution.

Built upon this framework, SciVLABench currently encompasses more than \textbf{20 representative laboratory scenarios} derived from contemporary scientific literature and automatically generates over \textbf{1,000 task templates} spanning \textbf{six evaluation dimensions}, including chemical knowledge, instrument knowledge, laboratory safety, fundamental laboratory operations, instrument operation, and spatial organization. The benchmark further incorporates more than \textbf{100 specialized laboratory assets}, supports over \textbf{30 robotic manipulation primitives}, covers multiple scientific disciplines including analytical chemistry and biochemistry, and automatically generates expert demonstration trajectories for every task template, providing a scalable resource for both benchmark evaluation and policy learning.

Our contributions are summarized as follows:

\begin{enumerate}
\item We introduce \textbf{SciVLABench}, a comprehensive benchmark that complements existing execution-oriented evaluation with a structured capability-oriented framework for scientific embodied intelligence.

\item We develop an automated task generation pipeline that enables scalable construction of diverse laboratory tasks together with expert demonstration trajectories for both benchmark evaluation and policy learning.

\item We establish a realistic laboratory simulation framework integrating high-fidelity physical modeling, dynamic laboratory interactions, and safety-aware assessment, providing a comprehensive testbed for advancing scientific embodied intelligence.
\end{enumerate}

\section{The SciVLABench Framework}
\label{sec:framework}

This section presents the technical architecture of SciVLABench, a data-driven Real-to-Sim task compilation framework. We describe the overall pipeline design and detail each major component, from instruction parsing to physics-based simulation execution.

\subsection{Overview}

SciVLABench employs a directed acyclic graph (DAG) pipeline architecture consisting of nine specialized nodes, as illustrated in Figure~\ref{fig:framework_overview}. The pipeline follows a strict data flow from natural language instructions to executable simulation tasks:

\begin{enumerate}
    \item \textbf{Analyzer}: Parses raw instructions into entity-bound neuro-symbolic ASTs
    \item \textbf{Normalizer}: Cleans data and assigns global unique identifiers (UIDs) to entities
    \item \textbf{Asset Manager}: Retrieves 3D models and binds them to physical instances
    \item \textbf{Skill Planner}: Orchestrates long-horizon action sequences via state-based Chain-of-Thought reasoning
    \item \textbf{Condition Planner}: Generates per-step physical verification criteria in parallel
    \item \textbf{Code Generator}: Synthesizes deterministic Python task files from templates
    \item \textbf{Registration}: Dynamically registers generated tasks into the VLABench framework
    \item \textbf{Simulation}: Executes tasks in MuJoCo physics engine with real-time condition checking
    \item \textbf{Reviewer}: Validates simulation outcomes via vision-based multimodal assessment
\end{enumerate}

This architecture embodies the principle of \textit{neuro-symbolic separation}: neural components (Analyzer, Skill Planner, Condition Planner) handle semantic understanding and reasoning, while symbolic components (Normalizer, Asset Manager, Code Generator, Simulation) ensure deterministic, physically-accurate execution.

\subsection{Neuro-Symbolic AST Parser}

The Analyzer node serves as the natural language understanding frontend of SciVLABench. Given a raw experimental instruction such as ``Pick up the beaker from the water bath and pour its contents into the test tube rack,'' the Analyzer produces a structured neuro-symbolic AST that captures both semantic intent and entity relationships.

\textbf{Entity Extraction.} The Analyzer employs a large language model to identify physical objects and their semantic attributes from the instruction. Each entity is assigned a placeholder identifier (e.g., \texttt{<beaker\_0>}, \texttt{<test\_tube\_0>}) and associated with attribute tags including object type, spatial relations, and functional properties. The extraction follows the principle of \textit{explicit intent only}: the analyzer does not infer implicit actions not stated in the instruction, ensuring faithful representation of the user's intent.

\textbf{Step Grounding.} The instruction is decomposed into a sequence of grounded steps, where each step references concrete entity identifiers. This creates a preliminary action graph where nodes represent entities and edges represent relationships (spatial, functional, or causal). For example, the pouring instruction yields steps such as: (1) approach \texttt{<beaker\_0>}, (2) grasp \texttt{<beaker\_0>}, (3) lift \texttt{<beaker\_0>} to height $h$, (4) tilt and pour into \texttt{<test\_tube\_0>}.

\textbf{Abstract Syntax Tree.} The grounded steps are organized into an AST structure that maintains the hierarchical and sequential dependencies between actions. Each AST node contains: (i) the semantic operation type, (ii) references to input/output entities, (iii) pre-conditions, and (iv) post-conditions. This formal representation serves as the canonical intermediate format consumed by subsequent pipeline stages.

\subsection{Automatic Scene Construction}

The Normalizer and Asset Manager nodes collaborate to transform the abstract AST into a concrete physical scene instantiation.

\textbf{Normalization and UID Assignment.} The Normalizer receives the AST with placeholder entity identifiers and performs several essential transformations: (1) \textit{Data cleaning}: standardizes entity names, resolves synonyms, and filters non-physical entities (powders, liquids) that cannot be directly manipulated; (2) \textit{Global UID assignment}: replaces placeholder identifiers with globally unique IDs that persist across pipeline stages; (3) \textit{Asset routing}: determines whether each entity should be retrieved from local cache, constant definitions, or the Objaverse asset library; and (4) \textit{Parameter translation}: converts semantic attributes into physical initialization parameters (positions, orientations, masses).

\textbf{Asset Retrieval and Binding.} The Asset Manager handles the physical instantiation of entities by: (1) querying the multi-tier asset cache (local files $\rightarrow$ constant definitions $\rightarrow$ Objaverse download); (2) performing dynamic class inference for entities with ambiguous types (e.g., distinguishing chemistry containers from common graspable objects); (3) injecting surgical XML modifications into MuJoCo model files to support specialized physics (e.g., adding solution sites to containers); and (4) performing fail-fast validation to ensure all required assets are available before proceeding to planning.

This separation of concerns---Normalizer handles semantic-to-physical translation while Asset Manager handles physical instantiation---enables clean modularity and facilitates error handling. The design principle of \textit{issuing commands, not performing manual labor} ensures that the Asset Manager never engages in LLM-based reasoning, but rather executes strongly-typed parameter-driven operations.

\subsection{Dual-Planner Compilation}

The core compilation intelligence resides in the parallel Dual-Planner, which consists of two cooperating planners that receive identical normalized context and asset status information.

\subsubsection{Skill Planner: State-based Chain-of-Thought Reasoning}

The Skill Planner addresses the challenge of long-horizon manipulation by employing a state-based Chain-of-Thought (CoT) planning approach. Unlike traditional planning systems that rely on hardcoded rules or iterative refinement loops, our planner operates as a \textit{stateful one-shot planner}:

\textbf{Pre/Post State Assertions.} For each action in the planned sequence, the Skill Planner explicitly specifies both the pre-state (conditions that must hold before execution) and post-state (conditions that result from execution). This enables precise tracking of entity states throughout the task. For example, before grasping a beaker: pre-state asserts that the robot end-effector is empty and the beaker is at its initial position; post-state asserts that the beaker is now constrained to the gripper and its position has changed.

\textbf{Skill Library Integration.} The planner draws from a library of primitive skills including: \texttt{pick}, \texttt{place}, \texttt{lift}, \texttt{drop}, \texttt{pour\_to\_entity}, \texttt{stir\_entity\_with\_tool}, \texttt{shake}, \texttt{insert\_to\_entity}, \texttt{unscrew\_cap}, \texttt{open\_drawer}, \texttt{wait\_for}. Each skill is parameterized with entity references and physical targets (heights, angles, durations).

\textbf{Zero Hardcoded Rules.} The planning process is entirely LLM-driven, with no hardcoded domain-specific rules. The planner's reasoning is guided solely by the state assertions and the skill library specifications, enabling generalization to novel task combinations.

\subsubsection{Condition Planner: Physical Verification Criteria}

In parallel with skill planning, the Condition Planner generates per-step physical verification criteria that enable rigorous task evaluation. This addresses a critical limitation of traditional benchmarks that rely on coarse-grained binary success metrics.

\textbf{Per-Step Condition Generation.} For each action step, the Condition Planner generates specific, physically-verifiable conditions. Rather than evaluating only final task completion, conditions are attached to intermediate states. For example, for a pouring task: (1) grasp condition verifies contact between gripper and beaker; (2) lift condition verifies beaker height exceeds threshold; (3) pour condition verifies liquid mass transfer between containers; (4) release condition verifies beaker placement at target location.

\textbf{Condition Types.} The condition library includes: \texttt{is\_grasped} (entity constrained to gripper), \texttt{lift} (entity at or above specified height), \texttt{on} (entity in contact with specified surface), \texttt{contain} (entity volume occupied by target substance), \texttt{pour\_into} (mass transfer between containers), \texttt{stir} (rotational motion applied), \texttt{cap\_open} (container lid state), \texttt{wait\_for} (state change after duration).

\textbf{Fan-in Architecture.} The parallel execution of Skill Planner and Condition Planner constitutes a \textit{fan-in} architecture: both planners receive identical inputs and operate independently, with their outputs merged at the Code Generator. This design maximizes efficiency by enabling concurrent processing while maintaining coherence through shared context.

\subsection{Dynamic Human Intervention Modeling}

A distinguishing feature of SciVLABench is its explicit modeling of dynamic human interventions, which are ubiquitous in real laboratory settings but absent from most simulation benchmarks. We introduce a mechanism for approximating human-robot interaction through \textit{programmatic environmental alterations}.

\textbf{Intervention Types.} SciVLABench supports several categories of interventions: (1) \textit{Instrument state toggles}: opening/closing valves, switching heaters on/off, activating stirrers; (2) \textit{Reagent additions}: introducing additional substances mid-task that may affect reaction dynamics; (3) \textit{Equipment reconfiguration}: repositioning support structures, changing container arrangements; and (4) \textit{External perturbations}: applying forces or disturbances to objects during execution.

\textbf{Implementation.} Interventions are specified as state modifications that alter the environmental conditions during task execution. They are injected programmatically through the Simulation node, which modifies entity states, adds or removes substances, or applies forces according to predefined intervention scripts. Each intervention is associated with timing information (when to trigger) and effect parameters (magnitude, duration).

\textbf{Evaluation Impact.} By introducing interventions, SciVLABench creates dynamic interference scenarios that evaluate an agent's ability to: (i) detect and respond to unexpected changes, (ii) adapt plans in response to altered conditions, and (iii) maintain task coherence despite external perturbations. These scenarios reveal robustness issues that would be hidden in static evaluation settings.

\subsection{Code Generation and Simulation}

The final stages of the pipeline transform the planned skill sequences and verification conditions into executable simulation code.

\textbf{Deterministic Code Synthesis.} The Code Generator operates as a deterministic template filler: given the normalized entity list, skill sequence, and condition specifications, it produces a Python task file with identical structure regardless of the specific task content. This deterministic property ensures \textit{reproducibility}: the same inputs always produce bit-identical outputs, facilitating debugging and result replication.

The generated code follows the VLABench task structure, defining: (i) a \texttt{ConfigManager} class that specifies entity configurations, initial conditions, and instruction text; (ii) a \texttt{Task} class that implements the \texttt{get\_expert\_skill\_sequence()} method returning the planned skill chain; and (iii) condition bindings that connect verification criteria to physics engine observations.

\textbf{Dynamic Registration.} The Registration node makes newly generated tasks discoverable by the VLABench framework without requiring process restart. It performs module cleanup, updates the dual name-to-config registry, and persists task configurations to enable retrieval by the evaluation infrastructure.

\textbf{Physics Simulation and Verification.} The Simulation node loads the registered task, initializes the MuJoCo physics environment with the configured scene, and executes the expert skill sequence. During execution, per-step conditions are evaluated against physics engine state observations. The simulation supports: (i) early termination upon condition failure, (ii) timeout protection for unbounded execution, (iii) HDF5-format data logging for observation/action trajectories, and (iv) video recording for visual inspection.

\textbf{Vision-based Review.} The Reviewer node provides an additional validation layer by employing a vision-language model to assess simulation outcomes. It extracts frames from simulation videos and prompts the VLM to verify whether conditions were satisfied according to visual evidence. This addresses cases where physics engine state may not fully capture task success (e.g., liquid spillage, object deformation).
